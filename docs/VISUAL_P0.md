# Визуальный апгрейд ×100, фаза 0: стенд кадров и быстрые победы

Первый спринт [плана визуального апгрейда](../VOIDBREAKER_Visual_Plan.md). Исходная база — `8dc893d` ветки `codex/cutscene-studio`, та же сборка, на которой снят разбор плана. Новых проходов рендера в фазе 0 нет: меняются шейдеры, числа и HUD. Каждое новое изменение вида включено по умолчанию и выключается флагом адреса.

## Стенд кадров `npm run beauty`

Стенд снимает одни и те же моменты на 844×390 и 1280×720, качество high:

- **этап:** `intro` — пролёт с титром, `wave` — 1.2 с после начала первой волны, `hit` — удар клинка по врагу, `finisher` — тяжёлый удар, `threat` — телеграф врага рядом с Пилотом, заполненный больше чем на 45 %;
- **Иерофант:** `intro` и бой в каждой фазе (`p1`–`p3`).

Пилот идёт к ближайшему врагу и бьёт серией. Враги снимаются через 3.5 с жизни, как в sweep. Босса через 6 с боя в фазе опускают до порога следующей фазы.

Кадры по моменту совпадают у любых двух сборок с одной симуляцией. Для этого:

- `Math.random` засеян, часы стоят;
- игровой цикл не идёт: мир шагает по 1/60 с;
- Web Audio выключен: синтез тратил случайные числа по своим таймерам;
- перед первым шагом пересеваются `Math.random` и `fxRng`.

Время мира каждого кадра пишется в `manifest.json`. Лист сравнения помечает пару, если момент разошёлся.

```bash
npm run build
BEAUTY_LABEL=after npm run beauty
npm run beauty -- --compare before after   # beauty/before-vs-after.html
```

Набор «до» снимается со сборки исходной ветки (`BEAUTY_DIST=<папка dist>`) или с текущей: `BEAUTY_URL='fx=off&cam=tactical'`.

**Что нашлось по пути.** Решения врагов берут числа из `Math.random`. Из того же потока брали и:

- частицы, следы на полу, пепел, пламя свечей, цифры урона и дрожь титров;
- фон арены: интервалы капель и колокола;
- ритм голоса Каэлис, вариант и высота каждого звука.

Поэтому любой новый эффект сдвигал ход боя. Теперь вся эта косметика берёт числа из `fxRng`, косметического потока из `core/rng`. Тест следит, чтобы в `vfx/`, `render/`, HUD, фоне арены и звуковом движке не появлялся `Math.random`.

При загрузке боя three.js тратит около 35.5 тыс. вызовов на UUID материалов и геометрий, поэтому стенд пересевает поток перед первым шагом. Пошаговая трасса 1-1, 1-3 и 1-9 на сборках «до» и «после» совпадает кадр в кадр: положения, состояния врагов, расход `Math.random`. Расходятся только подобранные осколки: их разлёт идёт из косметического потока, на бой он не влияет. Это первый шаг к тесту плана «бой с эффектами и без даёт одинаковую симуляцию».

| Наклон | 47° | 55° |

Кинокамеру получают новые и старые сохранения: поле заполняется значением по умолчанию при миграции. Пилот того же размера; на 1280×600 он не меньше 75 px в обоих режимах, это проверяет тест. Пролёт интро с декорацией приходит к углу обзора режима, а не к 30°. Без этого на конце крана угол скачком менялся бы до 38°. Кадры читаемости sweep сняты уже на новой камере.

## Решения и расхождения

- **Визор.** В «Пилоте 2.0» (`d66f1fe`) визор нарочно сделали тусклой щелью: белая сердцевина 2.0 с ореолом 0.9 читалась белым шаром. План и Master Plan §5.3 просят белую сердцевину. Поэтому щель осталась фиолетовой (1.0), а белой стала только тонкая линия внутри неё (1.6). Тест «визор — тусклая щель» переписан: белеет только линия не шире 13 см и не выше 1.5 см, эмиссия меньше 2.
- **Волны в подписи.** План требует только «титр этапа до волны». По правилу блока H «центр экрана принадлежит бою» туда же ушли и «Волна II/III»; флаг `title` возвращает оба титра.
- **Рамка босса** (Пилот не меньше 8 % высоты кадра) — следующий пункт C1. В фазе 0 изменился только наклон: с кинокамерой у боссов теперь 42°.
- **Тени на low.** Вытянутые пятна сейчас на всех уровнях качества: настоящих теней ещё нет. Фаза 1 оставит их для low.

## Проверка

- **`npm run check`:** типы, 43 файла и 387 тестов, сборка. Новых тестов 13:
  - флаги `?fx=`;
  - бюджет яркости D1;
  - вид телеграфов;
  - вытянутые тени и свет Пилота;
  - сворачивание титра до первой волны;
  - «Кино» для старых сохранений;
  - Пилот не меньше 75 px в обоих режимах камеры;
  - отсутствие `Math.random` в эффектах, фоне арены и звуковом движке.

  Сборка — 1.80 МБ при бюджете 2 МБ.
- **Браузерные проверки на итоговом коде:** smoke — 7 из 7, finishers — 243, choir — 20, studio-test — 116 проверок, ни одной ошибки. spectacle прошёл до последнего коммита (звук): 186 проверок на трёх разрешениях без ошибок.
- **sweep:** все 10 этапов выиграны в бюджете. Пик — Иерофант: 78 вызовов отрисовки и 127 тыс. треугольников при бюджете 160 и 260 тыс. У 1-9 кадр читаемости ловится не всегда: в нём должен атаковать враг в 7 м во второй волне. Это было и до правок: сборка «до» поймала его в 3 запусках из 8, новая — в 3 из 9. sweep не засеян; все остальные этапы дают кадр каждый раз.
- **Стенд:** по 49 кадров на каждом экране в наборах «до» и «после», без ошибок консоли. Все 98 пар совпадают по моменту. Набор «до» снят со сборки `8dc893d`, в которую внесены только два коммита косметического потока, иначе ход боя не совпал бы.
