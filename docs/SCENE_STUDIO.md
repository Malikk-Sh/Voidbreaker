# Студия сцен

Откройте `editor.html` на том же адресе, где размещена игра. Это дополнительный инструмент; основное меню ведёт в игру. Готовые новые сцены можно пересмотреть через `?watch=hierophantEnd`, `?watch=killGate` и `?watch=killBell`. Для локальной разработки: `npm run editor`.

Студия работает на Android в портретной и альбомной ориентации. Мышь и клавиатура не нужны. В ней доступны 24 постановки: восемь сценарных сцен, девять пролётов арен, появление/ярость/падение двух стражей и победа. Полные и короткие версии хранят собственные настройки.

## Как настроить добивание Иерофанта

1. Выберите **«Добивание Иерофанта»**. Кнопка **«Полная / Короткая»** переключает версии.
2. Перематывайте сцену ползунком. Кнопки `‹` и `›` сдвигают время на 1/30 с, скорость `0.1×…1.5×` меняет только просмотр. Нажмите фрагмент в таймлайне, чтобы перейти к его началу.
3. На вкладке **«Движение»** настройте начало, длительность, разгон, торможение, конечную точку, промежуточные точки пути и плавность разворота. Векторы задаются в метрах по осям сцены: вбок, вверх, вперёд. Промежуточные точки — отклонения от прямой между началом и концом, а не новые конечные позиции.
4. На вкладке **«Поза»** выберите клип, ключ и сустав. Углы задаются в градусах; можно добавлять и удалять ключи, менять их время, переход и высоту корня, скорость клипа и смешивание со старой позой. Длина клипа масштабирует его ключи и маркеры вместе. Сценический путь задаётся отдельно: движок подавляет X/Z и spin внутри позы.
5. Для `Удар в маску` нажмите **«Показать контакт с маской»**. Выбран точный кадр маркера, показано расстояние от кончика клинка до маски. После изменения ударной позы кнопка **«Совместить клинок с маской»** подбирает конечную позицию движения и его длительность под этот маркер. Затем проверьте замах и полёт до контакта.
6. На вкладке **«Сцена»** можно сдвигать стартовые позиции персонажей, добавлять свои движения и позы в текущем кадре и менять общий темп. **Общий темп** переносит камеры, движения, клипы и сюжетные события вместе; скорость просмотра сверху проект не меняет.
7. **«Просмотр в игре»** открывает выбранную версию сценического пересмотра в новой вкладке, без прохождения боя. Эта кнопка включает проект в игре. После просмотра вернитесь по ссылке «Студия сцен» или в прежнюю вкладку.

«Кадр» показывает постановочную камеру. «Облёт» разрешает вращать сцену одним пальцем, масштабировать и сдвигать двумя. Есть фиксированные виды сбоку и сверху. Камера редактируется через фрагмент на дорожке «Камера»; точки выбираются списками, чтобы не прокручивать десятки полей на телефоне.

Готовая постановка теперь находится в самих дорожках игры: казнь Иерофанта заменена прямым прыжком, ударом, взрывом и посадкой. Старые настройки цепи и прежних добиваний стражей не применяются к новой редакции этих сцен. Новые правки редактора сохраняют номер редакции дорожки. Кнопки отмены/повтора относятся ко всему проекту.

## Сохранение на Android

Правки автоматически сохраняются в хранилище **этого браузера на этом адресе**. Кнопка **«Применить в игре / В игре: включено»** включает или выключает весь проект. Отключение сохраняет черновик. Прохождение, награды и звёзды не редактируются; игровые пересмотры используют копию сохранения, как Кинозал.

Меню `⋯` содержит экспорт и импорт JSON. Экспорт скачивает `voidbreaker-scenes.json` в загрузки браузера. Храните копию файла: очистка данных сайта или режим инкогнито могут удалить черновик. На другом телефоне, в другом браузере или на другом preview-адресе файл нужно импортировать. Ошибочный импорт не заменяет рабочий проект.

Чтобы постановка вошла в общую сборку, экспортированный проект заменяет `src/data/sceneEdits.json`; включение `enabled` управляет её применением. Это отдельный шаг публикации исходников. Сама кнопка в браузере не отправляет правки в GitHub и не меняет продакшен.

## Что показывает площадка

Используются настоящие риги, геометрия, клипы, абсолютное время и Director игры. Перемотка восстанавливает состояние от начала, поэтому возврат к кадру не зависит от направления прокрутки. Смещения исходных движений применяются относительно живых якорей и направления сцены, чтобы перенос из эталонной постановки на реальное расположение босса не терял контакт.

Площадка нейтральная: без арены, звука, боевых частиц, физики разрушения и ввода игрока. В прологе показывается базовый полёт; в игре добавляются замедление, разрушение и управление падением. У пролётов арен эталонная камера снята без специального плана на декорацию: поправки переносятся на реальную игровую камеру. Окончательное кадрирование проверяйте в игре. Прямой отдельный пересмотр есть у восьми сценарных сцен; короткие боевые вставки также проверяются в соответствующем этапе.

Импорт разрешает менять постановку и добавлять движения/позы; добавленные шаги не могут вызывать произвольные сюжетные callbacks. Контактные события берутся из маркеров отредактированного клипа. Неизвестные ключи исходных шагов пропускаются, однако после изменения состава клипов в исходниках проект стоит проверить заново.

## Проверки

```bash
npm run typecheck
npm test
npm run build
npm run studio-test
npm run smoke
npm run spectacle
```

`studio-test` использует Playwright/Chromium и проверяет 412×915, 915×412 и 1280×800: все 24 постановки, конечность матриц и координат, воспроизводимость перемотки, точный контакт, сенсорные кнопки, хранение/отмену/повтор, экспорт/импорт, изменение ключевой позы, повторное совмещение контакта и запуск пересмотров в игре. Скриншоты и отчёт — `work/studio/`. Для системного Chromium задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`.

Это проверка мобильного интерфейса в эмуляции браузера; производительность и поведение загрузок на физическом Android отдельно не измерялись.
