# VOIDBREAKER

Мобильный веб-экшен-слэшер в космической готике (вид 3/4). **Вся графика, анимация, музыка и звук создаются кодом**: в репозитории нет ни одной модели, текстуры или аудиофайла, а иконки PWA рисуются при сборке. Готовые ассеты — только три открытых шрифта под лицензией OFL из пакетов `@fontsource`: Cormorant SC для заголовков, Philosopher для текста и Tektur для цифр. Логотип нарисован кодом — собственные глифы-полигоны.

Здесь собран играбельный вертикальный срез **Зоны 01 «Собор Падших Звёзд»**: 6 этапов, 2 Стража и босс Иерофант Скорби. Он закрывает объём MVP из `VOIDBREAKER_Concept.md` §9 и роадмапа `VOIDBREAKER_Tech.md` §29.

Дизайн-документы лежат в корне репозитория:

- `VOIDBREAKER_Concept.md` — концепция;
- `VOIDBREAKER_GDD.md` — геймдизайн;
- `VOIDBREAKER_Tech.md` — техническая архитектура.

ТЗ и визуальные ориентиры для следующих доработок:

- [Единый план улучшений](VOIDBREAKER_Master_Plan.md) — базовые правила и этапы разработки;
- [ТЗ на зрелищность, бой и постановку](VOIDBREAKER_Spectacle_Spec.md) — сценарии, порядок работ и критерии готовности;
- [Восемь визуальных референсов с пояснениями](docs/visual-references/README.md) — изображения в `docs/visual-references/` и указания по каждому кадру.

Изображения в `docs/visual-references/` — документация для разработки. Игра их не загружает; графика и остальные игровые ассеты по-прежнему создаются кодом.

## Быстрый старт

Нужен Node.js 20+ (CI работает на Node 22).

```bash
npm ci
npm run dev        # http://localhost:5173
```

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер Vite с HMR |
| `npm run build` | продакшен-сборка в `dist/`: манифест, иконки и service worker |
| `npm run preview` | раздаёт собранный `dist/` |
| `npm run typecheck` | TypeScript strict: игра, тесты и инструменты сборки |
| `npm test` | юнит-тесты (Vitest) |
| `npm run smoke` | e2e-дым на собранной игре (Playwright, Chromium); перед запуском нужен `npm run build` |
| `npm run sweep` | проход всех этапов Зоны 01 и босса на экране 844×390: победа, ошибки, бюджет отрисовки, кадры читаемости; нужен `npm run build` |
| `npm run spectacle` | Playwright-проверка казни и извлечения меча на трёх разрешениях: контакт, матрицы кадра, пропуск, повтор, сохранение; нужен `npm run build` |
| `npm run check` | typecheck, затем test, затем build |

Сборка весит около 1.3 МБ, из них около 280 КБ — gzip-JS и около 180 КБ — шрифты woff2 (только кириллица и латиница). Бюджет — 2 МБ, CI его проверяет.

## Управление

| Действие | Клавиатура и мышь | Тач | Геймпад |
|---|---|---|---|
| Движение | WASD / стрелки | плавающий стик (левая половина экрана) | левый стик |
| Атака / комбо | ЛКМ, J, Enter | кнопка атаки | X / □ |
| Заряженный удар | удерживать атаку | удерживать кнопку атаки | удерживать X / □ |
| Рывок | Пробел, Shift, K | кнопка рывка или свайп по правой половине | A / ✕ |
| Способности Q / E / ульта R | Q·E·R или U·I·O | кнопки способностей | LB / RB / триггеры |
| Пауза | Esc, P | кнопка паузы | Start |

Главные приёмы:

- **Ветки комбо.** Базовая серия — 4 удара; от неё ответвляются связки:
  - атака сразу после рывка — Рассечение → Восходящий месяц (подбрасывает врагов) → Звездопад (удар с прыжка, волна осколков);
  - пауза после второго удара — Шквал → Крест;
  - атака сразу после идеального уклонения — Контрудар: Пилот проходит сквозь цель.
- **Заряженный удар.** Пилот заносит клинок над головой; полный заряд выпускает серп-волну.
- **Идеальное уклонение.** Рывок в последние 0.15 с перед ударом — короткое мягкое замедление и окно Контрудара, без надписей на экране.
- **Оглушение.** У элиты, Голема, Стражей и боссов есть шкала оглушения — семь звёзд под полосой HP. Её наполняет мастерство: удары в окно уязвимости после атаки, полный заряд, Контрудар, идеальное уклонение. Вне окон спам почти ничего не даёт, шкала утекает. Оглушённый враг «плывёт», над головой кружат звёзды — по звезде на каждые полсекунды. После оглушения 5 с шкала не растёт, каждое следующее требует больше и длится меньше.
- **Раскол.** Финишер или полный заряд по оглушённому врагу взрывает трещины: урон по области, восполнение Резонанса, оглушение сразу заканчивается. Один Раскол на оглушение, мгновенных убийств нет.
- **Ранг комбо D…SS.** Растёт от разнообразных ударов, пока вас не задели, и увеличивает награду.

Раскладку тач-кнопок, автоприцел, тряску, вспышки, режим для фоточувствительных, штриховку телеграфов и режим «История» можно изменить в настройках (GDD §21). Там же, прямо из главного меню, включаются полноэкранный режим и меняется дистанция камеры.

## Параметры URL для разработки

| Параметр | Пример | Действие |
|---|---|---|
| `stage` | `?stage=1-3`, `?stage=boss1` | сразу открыть бой на этапе |
| `wave` | `?stage=1-6&wave=2` | перейти к нужной волне |
| `god` | `?stage=boss1&god` | бессмертие |
| `screen` | `?screen=hub`, `map`, `settings` | открыть экран меню |
| `q` | `?q=low`, `medium`, `high` | зафиксировать качество (автоподстройка отключается) |

Объекты для отладки в консоли: `window.__app` (автомат экранов и сохранение) и `window.__vb` (`game`, `battle`, `world`).

## Что реализовано

**Бой (GDD §5, §14)**

- Комбо из 4 ударов и ветки: Рассечение, Восходящий месяц, Звездопад, Шквал, Крест, Контрудар; заряженный удар с серп-волной.
- Рывок с кадрами неуязвимости и идеальное уклонение с окном Контрудара.
- Автоприцел с магнетизмом, оглушение и Раскол.
- Резонанс и ульта, ранг комбо.
- Ощущение удара: hitstop не дольше 120 мс за любые 250 мс, тряска, кик камеры, зум-панч, вибрация, частицы, шлейфы, ударные волны.

**Способности (GDD §6)**

- Серп Луны, Фазовый шаг, Гравитационный колодец и ульта Затмение.
- Уровни I–III и мутации A/B.

**Враги (GDD §9)**

- Шесть типов:
  - Шелуха — рой: бьёт когтями, прыгает на 4–6 м;
  - Шипник — веер из трёх игл;
  - Жнец — двойной рывок и вихрь косами;
  - Око — залп и луч, который ведёт за целью;
  - Обсидиановый голем — бросок глыбы навесом и удар с кольцевой волной;
  - Аколит Хора — щит союзникам и призыв Шелухи из пола.
- Перед каждым ударом виден замах: искры стягиваются к оружию или ядру, у тяжёлых врагов на полу сходится огненное кольцо.
- Модели собраны из деталей: панцири, костяные шипы и маски, бронзовые обручи, багровая ткань.
- Волны по 20–30 врагов, чтобы ульте было кого косить. У роя свой пул токенов атаки.
- Элитные аффиксы: Ускоренный, Взрывной, Зеркальный, Вампир.
- Директор волн с порталами и токенами атаки.

**Стражи и босс (GDD §11, Tech §17)**

- Система паттернов на таймлайне. Телеграф перед каждым ударом длится не меньше 0.8 с, это проверяют тесты.
- Страж Врат и Звонарь. На 50 % HP Страж впадает в ярость: ревёт, ускоряется и открывает приёмы второй фазы.
  - Страж Врат: серия из трёх ударов алебардой, три разлома веером, таран.
  - Звонарь: Резонанс (сначала бьёт кольцо, потом центр), Какофония с обломками колокола, призыв Шелухи.
- Иерофант Скорби в две фазы:
  - кольцевые волны с разрывами, кадила с дымом, призыв хора с щитом, падение колокола;
  - Литания — три веера игл;
  - во второй фазе арена обрушается в крест-мост над бездной; там он бросает кадила по мостам, бьёт Приговором (косой, затем прямой крест лучей) и поднимает Шелуху из бездны;
  - есть интро-пролёт камеры и кинематографичная смерть.

**Мета (GDD §3, §8)**

- Святилище: 4 ветки статов по 20 уровней. Каждый уровень дорогой, но заметный. Вехи на 3, 6, 10 и 15 уровнях открывают новые свойства: тройной разлом, лечение Расколом, второе дыхание, возврат Резонанса после ульты и другие.
- Кузня оружия, способности, реликвии, архив лора.
- Старые сохранения переносятся миграцией v1 → v2.
- Карта созвездий: ★-рейтинг этапов, врата босса открываются за 12 из 18 звёзд.
- Награды за этап считаются по формулам GDD.
- Сохранение в `localStorage` с контрольной суммой, записью через временный ключ и миграциями. Экспорт и импорт — строкой base64.

**Арены (GDD §17.4)**

У каждого этапа своя раскладка:

- 1-1 — базилика с апсидой;
- 1-2 — крестовый план из нефа и трансепта, колонны в средокрестии;
- 1-3 — двор Врат, который два провала делят на три прохода;
- 1-4 — кольцо вокруг свечного колодца;
- 1-5 — три острова и дальняя площадка над бездной;
- 1-6 — колокольня с проломленным полом.

Края провалов светятся. Враг, сброшенный ударом в провал, гибнет. На полу — ковровые дорожки, надгробные плиты, трещины со звёздным светом и обломки. На колоннах висят знамёна, из окон фасада падают лучи света.

**Кат-сцены**

- Пролёт камеры над ареной на старте этапа: название и реплика Каэлис.
- Появление Стража: низкий ракурс и титул. Ярость: наезд камеры. Гибель Стража: облёт в замедлении.
- Победный облёт Пилота и представление элиты.
- У босса — интро, переход фаз и смерть.
- Сцены, где камера управляется режиссёром, пропускаются атакой или рывком.

**Рендер (Tech §4–§7, §19, §20)**

- Three.js на WebGL2, фасеточная геометрия с цветом в вершинах.
- Обсидиановый matcap-материал, мокрый пол с отражениями-пятнами света.
- Риговые батчи: кости хранятся в float-текстуре, на каждый тип рига один draw call.
- Небо-шейдер с чёрной луной, свой dual-Kawase bloom и uber-пост: ударные волны, ACES, леттербокс, «иней».

**Анимация (Tech §8)**

- Клипы ключевых поз с кроссфейдами и событиями.
- Процедурная походка двуногих и многоногих.
- Ткань и цепи на Верле.

**Звук (Tech §21)**

- Синтез на Web Audio: SFX один раз запекаются через `OfflineAudioContext`.
- Генеративная музыка: слои A–D переключаются по интенсивности боя.
  - У каждого этапа своя эпическая тема: лад, темп и грув. В ней струнное остинато, медь, тайко и хорал.
  - У Стражей жёсткая тема в гармоническом миноре со скандирующим хором; в ярости добавляются двойная бочка и медь на каждую долю.
  - У Иерофанта — набат колоколов и «бумы».
  - Каждая песня звучит через свою шину, поэтому музыка меню не смешивается с боевой.
- Хор из формант, колокола из партиалов, сгенерированная реверберация, «голос» Каэлис.

**UI (Tech §22)**

- HUD на Canvas: готические полосы здоровья и Резонанса, медальоны способностей, щит ранга. Цифры урона набраны шрифтом Tektur.
- Меню на DOM и SVG поверх живой 3D-сцены, переходы диагональным «разрезом».
- Учтены safe-area и альбомная ориентация.

**PWA (Tech §27)**

- Манифест, PNG- и SVG-иконки (включая maskable) и service worker генерируются плагином `tools/pwa-plugin.ts`.
- После первого запуска игра работает офлайн.

## Архитектура

```
src/
  core/     ГПСЧ (mulberry32), математика, шина событий, пулы, шум, три шкалы времени
  data/     баланс и контент: герой, оружие, feel-профили, враги, способности, этапы, арены, лор
  gen/      генераторы: GeomBuilder и примитивы, процедурные текстуры, персонажи, арены зоны
  render/   рендерер, материалы, риговые батчи, небо, пост-обработка, ткань
  anim/     скелеты, клипы, локомоция, Верле, «кукла» персонажа
  world/    симуляция боя: герой, враги, бой, арена, камера, ранг, способности, директор волн
    enemies/  ИИ шести врагов зоны 1
    boss/     таймлайн паттернов, Стражи, Иерофант
  vfx/      частицы, шлейфы, кольца, телеграфы, обломки, свет
  audio/    синтезатор, рецепты SFX, движок, генеративная музыка
  game/     игровой цикл, Battle, FeelSystem (все «сочные» реакции подписаны на события), Cinematics (кат-сцены), App (экраны)
  meta/     сохранение, прогрессия, настройки
  ui/       HUD, шрифт, иконки, экраны меню
  input/    тач, клавиатура, мышь, геймпад и буфер ввода (150 мс)
tests/      юнит-тесты Vitest
scripts/    smoke.mjs — e2e-дым на Playwright; sweep.mjs — проход Зоны 01
tools/      pwa-plugin.ts — манифест, иконки и service worker при сборке
```

Ключевые принципы:

- **Детерминизм.** Сид этапа задаёт арену, сид врага — модель. Симуляция идёт с фиксированным шагом 60 Гц, мир и герой живут в разных шкалах времени.
- **Данные отдельно от кода.** Мувсеты, профили ощущений, волны и паттерны боссов описаны в `src/data` и `src/world/boss`.
- **Реакции — подписчики.** `FeelSystem` и VFX слушают `EventBus`. Симуляция ничего не знает о тряске, звуке и частицах.

## Тесты

`npm test` проверяет:

- детерминизм ГПСЧ и процедурной геометрии;
- формулу урона и формы хитбоксов (круг, дуга, линия, кольцо с разрывами);
- лимит hitstop и замедления;
- ранг комбо и буфер ввода;
- устойчивость ткани на Верле;
- таблицы стоимости статов и наград из GDD §8, звёзды и открытие врат босса;
- миграцию, экспорт и импорт сохранений;
- данные зоны;
- обрушение арены босса;
- корректность паттернов всех Стражей и босса, включая приёмы второй фазы Стражей.

`npm run smoke` проверяет собранную игру в Chromium: титул открывается, затем бот проходит начало этапа 1-1, и в консоли не появляется ошибок.

`npm run sweep` проходит каждый этап Зоны 01 и Иерофанта до победы на экране телефона 844×390 (около 5 минут): враги показывают телеграфы и снимаются, Иерофант — казнью. По этапу печатаются победа, ошибки консоли и пик вызовов отрисовки и треугольников за кадр; в `sweep/` ложится кадр боя с атакующим врагом рядом с героем — для проверки читаемости. Время кадра здесь не мерится: SwiftShader не похож на телефон.

`npm run spectacle` проверяет постановку на 844×390, 740×360 и 1280×720. Режиссёр проходит реальные маркеры клипов с шагом 1/60 с; проверяются контакт клинка с маской, передача оружия без скачка, положение ключевых точек внутри леттербокса, совпадение матриц скелета и батча, полный/короткий просмотр, ранний/поздний пропуск и изоляция сохранения Кинозала. В прологе сцена ждёт хвата: проход снимает кадр ожидания и «касается» экрана через 0.8 с; в казни проверяется, что контакт снят крупно (шлем и маска — не меньше 45 % высоты кадра). Кадры и `report.json` сохраняются в `spectacle/<качество>-<эффекты>-<текст>/`. Это проверка геометрии и состояний; обычную скорость анимации и работу на физических телефонах следует оценивать отдельно.

Для отдельных проходов доступны `npm run spectacle -- execution` / `extraction`, `SPECTACLE_VIEWPORT=844x390`, `SPECTACLE_MODES=full,short,skip-early,skip-late`, `SPECTACLE_Q=low|medium|high`, `SPECTACLE_EFFECTS=normal|reduced|off`, `SPECTACLE_TEXT=1` и `SPECTACLE_OUT`. Диагностический `off` отключает bloom, вспышку и дополнительные частицы; тело, оружие и цепь остаются видимыми. Smoke, sweep и spectacle используют браузер Playwright; при необходимости системный Chromium выбирается через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`.

Первый пакет реализации [ТЗ на зрелищность](VOIDBREAKER_Spectacle_Spec.md) описан в [отчёте P0](docs/SPECTACLE_P0.md).
